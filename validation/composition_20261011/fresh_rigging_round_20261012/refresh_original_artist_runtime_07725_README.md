# Future original-artist runtime refresh only

`refresh_original_artist_runtime_07725.py` is Source preparation, not execution authorization. It has no automatic entry point. Root may invoke `run(...)` once in the **already running original artist process**, only after a fresh Parent resource scope, fresh PID/FILETIME verification, a successful latest803 SaveCopy, and actual successful OriginalClone control plus one manual Sync. None of those native results currently exists.

The operation changes the registered Character Designer runtime from the actual cached .77.24 to the complete approved .77.25 deployment. It does not open a file, save the artist, Attach a work item, restore/re-adopt a Rig, evaluate a frame, perform Undo, start a worker, or apply a repair. Those subsequent artist operations require their own reviewed sequence.

## Preservation and rollback

Before unregister, the script reads the actual cached .24 runtime. It never imports disk .25 into that old namespace to check idle state. The unchanged oracle's exact CD display/Forearm dependencies must already be cached from the actual runtime; a missing dependency stops before disable. Existing cached animation jobs/scans, Tweak sessions and owned editing sessions block refresh. Only actual nonempty Centreline/Delta capture or runtime state blocks their destructive unregister seam; idle available controls and false/stale WM availability flags do not constitute a capture. Captures are not transferred or silently cleared.

The unchanged f220 verifier and260b preservation oracle supply the proven registration and asset comparisons. The803 light reader independently captures full old Worklist RNA, Rig/data/session metadata, raw Rest, context, modifiers and identities. Every old Scene field is compared recursively, including nested collection items and native ID pointers. The only permitted new persistent Scene fields are empty `workspace_path` and `workspace_identity` defaults on existing Worklist rows. The script never rewrites Scene data. Only changed WM scalar/ID fields are restored with the historical verifier; changed WM collections fail.

All Actions and slots must have complete selected-slot content proofs from the exact old .24 fingerprint helper. Unsupported content stops before unregister and stays **Unknown**. This is separate from dependency/graph Known, which is not inferred. Raw asset, pose/context, modifier and all native ID/user inventories must remain exact after registration. New WM schema defaults are recorded separately.

The historical .24 manifest c72 declares159 verified leaves, totalling4,640,192 bytes. Its old tree also has113 historical bytecode cache files; they remain untouched. During the future authorized refresh call, only those159 exact source leaves are copied to `output_root/rollback07724_source/character_designer`, with path, hash and exclusive-write guards. A candidate **registration failure** may use this fresh cache-free tree for module-only rollback to .24. It does not restore data, clear artist data, switch Scene, reopen a file or invoke Undo. Candidate-disable/rollback/check failures remain recorded failures. A successful registration followed by a preservation failure stops; it does not attempt a data repair.

Undo history remains **Unknown** across addon unregister/register; no Undo operation or reset is performed and no claim of Undo-stack preservation is made. The fresh SaveCopy remains the recovery artifact. A refresh receipt can claim completion only for this runtime refresh and its actual preservation checks, not original Rigging Attach/Sync/Unity acceptance.
