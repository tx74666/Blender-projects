# Fresh official Cosha control/save probe

This is a Source-prepared, partial native acceptance harness. It has not been
executed. A fresh Parent-owned headful resource grant and the reviewed complete
new package are required before an external launcher runs it. It never opens
the artist file, invokes Sync, starts a worker, updates a Link revision, publishes
an animation or applies anything in Unity.

## Inputs and isolated launch boundary

The caller supplies actual path/SHA pairs for the successful
`randomrealm.two-arm-real-prepare/1` report, protected artist file, new Source
freeze and official complete package manifest. The harness derives the actual
Workspace, Link, WorkID, model, complete packet, independent Target-input asset
and weapon assets from that pinned Prepare report. It never creates an identity
or substitutes the input draft UUID for the genuine WorkID.

Required arguments are `--prepared-report`, `--prepared-report-sha256`,
`--protected-artist`, `--protected-artist-sha256`, `--source-freeze`,
`--source-freeze-sha256`, `--package-manifest`, `--package-manifest-sha256`,
`--script-sha256`, `--unity-project-root`, `--output-root`, `--profile-root`, and
`--confirm-isolated-headful`. Optional reference input requires both
`--reference-packet` and `--reference-packet-sha256`. `--quit-on-completion`
only requests normal quit; an external owner must record actual natural exit.

Use a factory headful Blender 5.2 process with autoexec disabled and one real
Window. The output root must already be an empty child of this validation
directory. Use a separate short fresh profile root containing only empty
`CONFIG` and `DATAFILES`; its environment and actual Blender resource paths must
agree. The Source-cache derived path must remain below 260 UTF-16 units. The
profile and outputs must stay outside the Unity project and protected artist.
The external launcher owns process/resource isolation and its grant receipts.

The new package uses the official `release_projection.py` file-map schema.
Every package file is pinned, no additional file is admitted, and every loaded
`character_designer` module must have its actual `__file__` and SHA inside that
same root. Registration uses the whole add-on's normal `register()` path.
Older r4 packages without the fresh ARM setup bridge cannot satisfy admission.

## What a successful native run would prove

The harness calls public Worklist Connect, Add the exact real row with
`activate_new=False`, and Activate Custom. The fresh importer must produce its
authenticated ARM setup proof; no old artist Rig, copied row or prebuilt native
graph is substituted. Both Source/Custom base clocks, both Action slots,
complete captured input provenance and the twenty-component carrier are checked.

In actual native RIGGING Tweak, each of the four real Target/Hint controls is
translated and explicitly saved with `key_current`. The real operator must
finish and produce a finite positive native/input delta while formal Custom and
read-only Source curves remain unchanged. Collect retains actual Known/Unknown
and dirty status; Unknown is never promoted. Real Undo and Redo occur on separate
timer ticks and reacquire native IDs through the registered lifecycle callbacks.

If a complete reference packet is supplied, only the public prepare/set reference
APIs are used. The actual reference BASE strip and normalized clock are checked;
three existing samples must show a finite positive lower-body pose difference.
Formal Base, Source, twenty input curves and local Return remain unchanged, and
restoring the formal Base must recover the original lower-body preview.

The enabled BASE preview is saved with transient Tweak ended. Mainfile reopening
happens after the old override exits; the next tick checks cache restoration
before manual current/Activate and requires all five owned callbacks exactly
once. Native controller names, constraints, collections and both Pose/Bone
palette/custom RGB data are protected by a plain presentation digest.

The report records the exact local fourteen-field Return, protected Action motion
hashes, actual saved scene, complete preserved inputs and owned weapon geometry
proof. The original complete weapon payload and whole packet SHA remain intact.

## Explicit limits

No result exists yet. Even a successful control/save run would not prove visible
UI buttons/screenshots, gun appearance, FK leg editing, deform/hold-pose output,
physical FBX/sidecar publication, Unity Apply, game runtime, batch/masks or Original
X Rig compatibility. The new Rig is an isolated experiment, not a chosen artist
replacement. Raw saved Rig weights are recorded unchanged; global preview intent
does not fabricate a deformation witness. Physical single/manual Sync and Unity
application need their separate admitted phases and genuine evidence.

Exceptions persist a failure report and stop the timer without retry or
publication. Existing outputs are not overwritten except the harness's own
durable progress report. The external owner remains responsible for process
closure, natural exit and resource return.
