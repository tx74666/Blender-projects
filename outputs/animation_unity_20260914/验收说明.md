# Character Designer 动画流程：第一阶段交付与验收

2026-09-14，本地发布 Character Designer 0.59.0、RR Helper 0.2.12。

**动画导入、预览和恢复流程已实现并安装。当前 X 的完整角色验收尚有一项未通过：原小臂校准已因网格拓扑变化失效。** 这项数据问题没有被自动重捕获或覆盖。

## 使用

1. Unity：`Tools > Character Designer > Animation`，选择 Cosha.Player 与现有 Walk，使用 Preview、Play/Pause、时间滑块检查。拖动预览图旋转视角，滚轮缩放。
2. 点击 `Send Test Animation to Blender`。正式窗口已实测发送成功。
3. Blender：刷新已安装插件后，`Character Designer > Animation > Import Latest from Unity`。默认交接目录是 `D:\Blender\Projects\Character\Animation\UnityExports`。
4. 得到唯一命名的独立 `Unity Test · Walk` Action。可播放、暂停、拖时间轴；Restore/Cancel 恢复原 Action/Slot、NLA、姿势、播放状态、帧范围、帧和子帧。

保留了可直接检查的独立文件：[Cosha_Walk_review.blend](Cosha_Walk_review.blend)。这个副本保存了测试 Action 和持久恢复记录，不替代用户的 X.blend。恢复后测试 Action 仍保留；重新进入完整预览请用 Import Latest，而不是只在普通 Action 下拉框重新挂载。

## 修改

- Unity 使用原 Avatar 和隔离 PreviewScene/Playable，采集 Cosha 实际评估后的运动；60 Hz，包含准确结束时刻。原地 Walk 的 Root 轨迹保留。
- Blender 使用独立 Unity 姿态适配，不经过 Kimodo 比例调整或二次重定向。
- Humanoid 会平移部分相连关节。必要时只给同一 Rig Object 临时换一份 Armature **数据副本**，在副本上允许关节平移；原 Armature 数据不改。Restore 换回原数据 ID 并清理未共享副本。
- 预览中新增结构编辑、共享原骨架被外部改动时，阻止会丢编辑的恢复，保留数据。失效的小臂校准错误会显示在 Animation 页面。
- RR 的旧 Animation 页面和旧 Unity 同步入口已隐藏/重定向；旧兼容服务保留。武器调试、Animation.blend、动画资源、Avatar、Animator/Controller 保留。
- RR 先核对并合入本机 0.2.11 较新修复，再发布 0.2.12，避免建筑、资产导出降级。

## 未通过与验证边界

**当前 X：Cosha 为 3788 点，保存的小臂校准及 Unity 导出源为 3795 点。** 插件正确报告 `Mesh topology or rig chain changed` 并停用失效校正。没有删除旧校准，没有尝试按错误索引重新套用。当前 X 的小臂校正必须在当前网格重新捕获并更新导出后，再作完整同版验收。

找到拓扑完全匹配的旧固定源，在明确隔离旧 Setup 的后台诊断副本里验证同一 Walk：小臂 **校正开－校正关** 的真实网格差，五个时刻最大为 **0.426 微米**；Root 转向后的额外校正协变误差 **0.359 微米**。这证明同版校正链路可用，不能替代当前 X 校准的验收。

普通皮肤的差异也已实际分解：Blender 在蒙皮后细分，Unity 在细分后的网格上蒙皮；Unity 当前为 `FourBones`，三件 SMR 为 Auto。仅在诊断副本模拟相同顺序与最终四权重后，Clothes / Stocking 最大误差降到 **1.013 / 1.167 微米**。原模型的修改器和权重保持不变。

旧导出 Cosha 的 16,591 个有权重顶点同条件误差最大 **2.768 微米**；另外 6 个接缝重复点来自旧原生无权重点 3574 / 3575，仍记录为失败。当前源与旧 FBX 不同版，不能用最近顶点配对宣称精确皮肤一致。

当前 Walk 是原地循环；本次没有实测带位移的其它 Root Motion clip。Blender Action → Unity 回传、实时双向同步、头发/裙子物理不属于这次新增实现。
